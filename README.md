# TeraCoffee

커피 메뉴 조회, 포인트 충전, 주문/결제, 인기 메뉴 조회 기능을 제공하는 커피 주문 시스템입니다.

## 문제 해결 전략

이 과제에서 가장 중요하게 본 부분은 포인트 결제의 정합성입니다. 포인트는 금액성 데이터이기 때문에 동시에 여러 주문이 들어와도 잔액이 음수가 되면 안 된다고 판단했습니다.

다중 서버 환경에서는 애플리케이션 메모리 기반 락이 공유되지 않기 때문에, 동일 사용자의 포인트 지갑 row를 DB에서 잠그는 방식으로 동시성을 제어할 계획입니다.

## API 설계

| 기능 | Method | URL |
| --- | --- | --- |
| 커피 메뉴 목록 조회 | GET | /api/v1/menus |
| 포인트 충전 | POST | /api/v1/points/charges |
| 커피 주문/결제 | POST | /api/v1/orders |
| 인기 메뉴 조회 | GET | /api/v1/menus/popular |

## ERD 초안

- coffee_menu: 커피 메뉴 정보
- point_wallet: 사용자별 포인트 잔액
- point_history: 포인트 충전/사용 이력
- coffee_order: 주문 원장
- order_outbox: 주문 이벤트 전송 대상

## 기술 선택 이유

- Spring Web MVC: HTTP API 구현
- Spring Data JPA: 도메인 중심의 데이터 접근
- MySQL: 트랜잭션과 row lock 기반 정합성 검증
- Testcontainers: 실제 MySQL 환경에 가까운 통합 테스트
- REST Docs: API 명세와 테스트의 연결

## 동시성 전략

포인트 충전과 차감은 point_wallet row를 기준으로 처리합니다. 주문 결제 시 사용자 지갑을 비관적 락으로 조회하고, 잔액 검증과 차감을 하나의 트랜잭션 안에서 수행합니다.

## 데이터 일관성 전략

주문, 포인트 차감, 포인트 사용 이력, 주문 이벤트 outbox 저장은 하나의 트랜잭션으로 묶습니다. 외부 데이터 플랫폼 전송은 실패 가능성이 있으므로 주문 트랜잭션 안에서는 전송 대상 이벤트를 먼저 저장하고, 커밋 이후 전송하는 방식으로 분리합니다.

## 향후 개선 계획

- outbox 이벤트 재시도 스케줄러 추가
- 인기 메뉴 집계 캐시 또는 별도 통계 테이블 검토
- 주문 중복 방지를 위한 idempotency key 검토
